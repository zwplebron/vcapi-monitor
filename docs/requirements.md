# 需求规格说明书

## 项目概述

一款运行在 macOS 上的桌面悬浮窗软件，实时监控 Deepseek 开放平台的账号用量数据。

## 用户角色

- 普通用户：Deepseek 开放平台的使用者，需要实时了解账号余额和用量情况

## 功能需求

### F1: 账号绑定
- 首次启动时，显示绑定窗口，用户输入 Deepseek API Key
- 提供"如何获取 API Key"的帮助指引
- 绑定后 API Key 加密存储在本地
- 关闭软件重新打开时无需重新绑定

### F2: 实时用量监控
- 显示剩余金额（总余额，单位：元）
- 显示本日消费金额和 Tokens
- 显示本周消费金额和 Tokens
- 每 5 分钟自动刷新数据
- 支持手动刷新（手动刷新后 5 分钟计时器重置）

### F3: 余额指示灯
- 交通信号灯样式（红、黄、绿三灯并排）
- 绿灯：余额 > 10 元
- 黄灯：2 元 < 余额 ≤ 10 元
- 红灯：余额 ≤ 2 元
- 仅当前区间对应的灯亮起，其余为灰色

### F4: 悬浮窗控制
- 窗口始终置顶于桌面（可切换）
- Pin 按钮：一键切换置顶/取消置顶
- 隐藏按钮：隐藏窗口，程序后台运行
- 全局快捷键 `Cmd+Shift+D`：快速显示/隐藏窗口
- 关闭按钮：退出程序

### F5: 账号管理
- 查看当前绑定的 API Key（部分隐藏显示）
- 解绑账号（清除配置，回到绑定窗口）
- 更换绑定（更新 API Key）

### F6: 单账号模式
- 仅支持绑定一个账号
- 无需账号切换功能

## 非功能需求

### N1: 环境要求
- 操作系统：macOS
- 无需用户手动安装任何依赖
- 双击 .app 即可运行

### N2: 性能
- 启动时间 < 3 秒
- 数据刷新延迟 < 5 秒（API 响应时间除外）
- 内存占用 < 100MB

### N3: 安全性
- API Key 不在本地明文存储
- 所有 API 请求通过 HTTPS

### N4: 兼容性
- 支持 macOS 10.15 (Catalina) 及以上版本

## 界面风格

- 简洁直观，主色调淡蓝色
- 悬浮窗约 280x340 像素
- 可拖动到屏幕任意位置

## V2.0.0 新增需求草案

### V2-F1: 双服务余量监控
- 在现有 Deepseek 余额监控基础上，新增 ChatGPT Codex 额度监控。
- Deepseek 余量单位为元（¥）。
- Codex 余量单位需先通过技术验证确认；当前候选为 credits。
- 两种服务的余量都需要显示剩余百分比，让用户直观看到还剩多少可用额度。
- 若某服务无法计算百分比，界面需明确显示“百分比不可用”或隐藏百分比，避免误导用户。

### V2-F2: 账号绑定
- 首次启动时支持同时绑定 Deepseek 和 Codex。
- 用户可以只绑定 Deepseek、只绑定 Codex、或同时绑定两者。
- Deepseek 继续使用 API Key 绑定。
- Codex 绑定方式需先通过技术验证确认，不能在验证前假设存在公开 API Key 或稳定接口。

### V2-F3: 顶部状态栏显示模式
- 当仅绑定一个服务时，状态栏默认显示该服务余量。
- 当同时绑定 Deepseek 和 Codex 时，用户可在设置中选择状态栏显示模式：
  - 只显示 Deepseek
  - 只显示 Codex
  - 同时显示 Deepseek + Codex
  - Deepseek / Codex 交替显示
- 交替显示需要默认间隔，建议 5 秒。

### V2-F4: 服务图标
- Deepseek 和 Codex 需要分别配置小图标，用于状态栏、悬浮窗、设置页区分服务。
- 图标先使用自定义简洁图标，不直接依赖官方商标素材。
- 建议图标规格：
  - 16x16 或 18x18 PNG：用于状态栏和紧凑标签
  - 32x32 PNG：用于设置页或主界面
  - 透明背景，深浅背景均可辨识
- 建议存放路径：
  - `assets/icons/deepseek.png`
  - `assets/icons/codex.png`

### V2-F5: 悬浮窗界面改版
- 主悬浮窗需要同时支持 Deepseek 和 Codex 两种余量展示。
- 每个服务区域显示：服务图标、服务名称、余量数值、单位、剩余百分比、状态灯、更新时间。
- 状态灯由当前三灯并排改为单灯模式：
  - 绿色：余量充足
  - 黄色：余量偏低
  - 红色：余量不足
  - 灰色：未绑定、未知、获取失败
- Deepseek 与 Codex 的红/黄/绿阈值需要分别设置。

### V2-F6: 技术验证前置
- 在进入 V2.0.0 正式开发前，必须先验证 Codex 额度是否能自动获取。
- 验证内容包括：
  - 是否存在官方可用接口
  - 是否能获取总额度、已用额度、剩余额度
  - 是否能计算剩余百分比
  - 是否需要 ChatGPT 登录态
  - 是否适合普通用户长期稳定使用
- 若无法自动获取，需提出替代方案并经审核后再开发。
